The new measure

Google now grades whether an AI agent can actually use your site.

PageSpeed Insights is the tool the whole industry uses to grade a website. For years it reported four scores: Performance, Accessibility, Best Practices and SEO. It now reports a fifth, sitting right beside them — Agentic Browsing. Google's own description: “These checks ensure high-quality, browsable websites for AI agents.”

Three checks, run separately on phone and desktop. Here is what each one asks, and how the current site does:

  • ×Is the page's structure readable to a machine? Google calls this the accessibility tree — the same map a screen reader uses. On the current site it reports “not well-formed”.
  • ×Does the page hold still while it is read? Content that jumps around loses an agent partway through. The current site's desktop layout shift measures 0.687, where anything above 0.1 is considered poor.
  • ×Is there an llms.txt file? A short plain-text index that tells an AI what your site contains. The current site does not have one; the rebuild does.

Reading it fairly: Google labels this category “still under development and subject to change”, so nobody can call it a ranking factor yet. And two of the three are quick to fix — an llms.txt file is one afternoon's work. The point is not that they are hard. It is that a year into AI assistants answering patient questions, nobody had done them.

Checked live · 4 August 2026

Their admin username is published on the open internet.

  • ×The username is public. That endpoint hands the administrator account name to anyone who visits it. This is WordPress's default behaviour rather than a mistake unique to them — but on a site whose login page is also reachable, it should have been switched off.
  • ×The login page answers to anyone. /blog/wp-login.php is reachable from the public internet, so there is a door to type that username into.
  • ×Four standard browser protections are switched off. These are the instructions a site sends telling a visitor's browser to always use a secure connection, to refuse to be impersonated inside another site, and to stop leaking which page someone came from. The rebuild sends all of them; in fairness, the current site does set one that the rebuild was missing until today, and that is now fixed too.

Being precise, because this matters: no password is exposed and there is no sign anyone has broken in. What is exposed is the username — one of the two things needed to get in — next to a door that opens. To be clear about scope: your main site is already plain static pages; it is the blog that runs on WordPress, and that is where this comes from. The rebuild has no WordPress install at all, so there is no login page and no admin account to find.
